# V22 — строгая и быстрая запись через YCLIENTS

Цель: исправить не UI-косметику, а фактическую логику записи.

## Что исправлено

1. Связка `услуга -> специалисты` теперь строгая из YCLIENTS.
   - Backend использует `/book_staff/{companyId}?service_ids[]=SERVICE_ID` как источник истины.
   - Общий список специалистов больше не расширяет список для конкретной услуги.
   - Если YCLIENTS возвращает 2 специалистов для услуги — приложение показывает 2.
   - Если YCLIENTS возвращает 1 специалиста — приложение показывает 1.

2. Время и даты берутся через рабочий live endpoint `/book_times/{companyId}/{staffId}/{date}`.
   - Bootstrap проверяет ближайший горизонт дат параллельно.
   - Перед созданием записи выбранный слот заново проверяется live в YCLIENTS.
   - Старые слоты не считаются подтверждением записи.

3. Экран записи не пересоздаётся при переходе между вкладками.
   - Shell использует `IndexedStack`.
   - Переход `Чат -> Запись` не должен сбрасывать выбранные услугу/специалиста/дату/время.

4. Убрана подстановка чужой demo-длительности для реальных YCLIENTS услуг.
   - Если YCLIENTS дал длительность — показывается она.
   - Если не дал — поле остаётся пустым, а не подставляется от другой demo-услуги.

5. Telegram/клиентские технические строки из V18 сохранены очищенными.

## Что проверено в контейнере

- `backend npm run build` — OK
- `backend npm run lint` — OK
- backend start — OK
- `/health` — OK
- `/yclients/booking/bootstrap` route зарегистрирован и отвечает
- ZIP integrity — OK
- Активного `.env` внутри архива нет
- Символы битой кодировки replacement-character не найдены

## Что невозможно проверить без твоих токенов и YCLIENTS

- Реальное количество специалистов по каждой услуге.
- Реальные окна времени.
- Реальное создание записи.

Но логика теперь устроена так, что приложение не должно само добавлять лишних специалистов к услуге.
