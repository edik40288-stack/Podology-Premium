# Архитектура

## Общая схема

```text
Flutter App iOS/Android
        |
        | HTTPS / WebSocket
        v
NestJS Backend
        |                 |
        | HTTPS           | S3/R2/MinIO или локально на dev
        v                 v
YCLIENTS API          Media Storage
```

## Mobile App

Основные зоны:

1. Регистрация / вход
   - номер телефона;
   - VK;
   - подтверждение;
   - имя и фамилия.

2. Главная
   - баннер;
   - кнопка «Записаться на приём»;
   - «О центре»;
   - «Описание»;
   - «Сертификаты»;
   - «Интерьер»;
   - «Наши работы»;
   - «Наши услуги»;
   - «Наши специалисты».

3. Услуги
   - список услуг;
   - цена;
   - длительность;
   - карточка услуги;
   - переход к записи.

4. Запись
   - выбор услуги;
   - выбор специалиста;
   - выбор даты;
   - выбор времени;
   - создание записи в YCLIENTS.

5. Чат
   - текст;
   - фото;
   - видео;
   - история сообщений;
   - push-уведомления на следующих этапах.

6. Профиль
   - личные данные;
   - мои записи;
   - уведомления;
   - конфиденциальность;
   - выход.

## Backend

Backend отвечает за:

- безопасную работу с YCLIENTS;
- выдачу услуг/специалистов/дат/времени в приложение;
- создание записи;
- чат;
- загрузку фото/видео;
- будущие push-уведомления.

## YCLIENTS

YCLIENTS остаётся источником правды для:

- услуг;
- цен;
- специалистов;
- расписания;
- свободных окон;
- записей;
- клиентской базы.

## Что нельзя делать

- нельзя хранить Partner Token / User Token в приложении;
- нельзя дублировать цены вручную в мобильном приложении;
- нельзя строить свою CRM вместо YCLIENTS на этом этапе;
- нельзя делать чат через костыль в комментариях к записи — чат должен быть отдельной сущностью.
