# YCLIENTS Integration Notes

## Что подтверждено по документации

YCLIENTS даёт API-доступ к данным клиентов, записей, услуг и другим сущностям. Для части методов нужен User Token системного пользователя с нужными правами. Partner Token и User Token должны храниться только на backend.

## Используемые направления API

В текущий каркас заложены методы:

- получить услуги;
- получить сотрудников;
- получить доступные даты;
- получить доступное время;
- создать запись.

## Почему endpoint'ы вынесены в backend

Мобильное приложение не должно знать токены и прямые URL YCLIENTS. Если API YCLIENTS поменяется или понадобится другая схема авторизации, меняется backend, а приложение остаётся стабильным.

## Что надо проверить на реальном аккаунте

1. Точный `company_id`.
2. Точный `form_id`.
3. Работает ли онлайн-запись через `book_*` методы для этого филиала.
4. Какие услуги открыты для онлайн-записи.
5. Какие сотрудники открыты для онлайн-записи.
6. Нужно ли подтверждение записи администратором.
7. Нужна ли предоплата.
8. Какие поля обязательны при создании записи.

## Важный риск

YCLIENTS может иметь различия между публичной записью через форму и внутренним API приложения. Поэтому первый технический тест после получения токенов — не дизайн, а проверка пяти запросов: услуги, сотрудники, даты, время, создание тестовой записи.

## P53 thin backend mode

В P53 добавлен режим, где YCLIENTS становится основным источником данных по клиентам и записям, а backend работает как безопасный прокси.

```env
APP_OPERATING_MODEL=thin_proxy
BOOKING_PROVIDER=yclients
PROFILE_PROVIDER=yclients
```

В этом режиме Flutter-интерфейс не меняется: клиент всё так же выбирает услугу, специалиста, дату и время внутри приложения. Но данные приходят из YCLIENTS, а созданная запись хранится в YCLIENTS.

## Дополнительные endpoint-шаблоны

Для части операций YCLIENTS/Altegio может потребоваться уточнить реальные URL и права аккаунта. Поэтому P53 поддерживает настраиваемые endpoint-шаблоны:

```env
YCLIENTS_BOOKINGS_ENDPOINT_TEMPLATE=
YCLIENTS_CLIENT_UPSERT_ENDPOINT_TEMPLATE=
YCLIENTS_CLIENT_DELETE_ENDPOINT_TEMPLATE=
YCLIENTS_CLIENT_DELETE_MODE=request
```

Поддерживаемые плейсхолдеры:

```text
{companyId}
{formId}
{phone}
```

Пока эти переменные пустые, приложение не падает: backend использует технический cache/reference. После проверки реального API они заполняются и YCLIENTS становится source of truth.

## Что надо проверить первым с реальными ключами

1. `/yclients/status` показывает configured=true.
2. `/yclients/services` отдаёт реальные услуги.
3. `/yclients/staff` отдаёт реальных специалистов.
4. `/yclients/dates` и `/yclients/times` отдают окна.
5. `/yclients/booking` создаёт реальную тестовую запись.
6. Endpoint получения записей по телефону работает и заполняется в `YCLIENTS_BOOKINGS_ENDPOINT_TEMPLATE`.
7. Endpoint создания/обновления клиента работает и заполняется в `YCLIENTS_CLIENT_UPSERT_ENDPOINT_TEMPLATE`.
8. Регламент удаления/обезличивания клиента согласован и отражён в `YCLIENTS_CLIENT_DELETE_ENDPOINT_TEMPLATE` или в ручном процессе.
