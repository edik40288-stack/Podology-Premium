# P53 — глубокий аудит перед переводом на YCLIENTS + Telegram thin backend

Дата: 2026-06-22
База: P52 ready final

## Цель

Сохранить текущий интерфейс приложения и сценарии клиента, но убрать роль собственной базы как главной CRM.

Новая модель:

```text
Android/iPhone приложение
→ тонкий backend на сервере
→ YCLIENTS: клиенты, услуги, специалисты, расписание, записи, отмены
→ Telegram: чат, фото, видео, ответы администратора
→ маленькая техническая БД: сессии, согласия, связки, индексы сообщений
```

## Что уже было в P52

- Flutter-приложение Android/iOS.
- NestJS backend.
- Авторизация по телефону.
- Профиль клиента.
- Экран записи внутри приложения.
- Экран «Мои записи» внутри приложения.
- Отмена записи с правилом 48 часов.
- Чат внутри приложения.
- Отправка фото/видео в чат.
- Telegram-мост клиент ↔ админ.
- YCLIENTS endpoints: services, staff, dates, times, booking, cancel.
- Юридический пакет РФ.
- Единый `.env.example`.

## Что было проблемой

P52 технически могла работать как собственная система:

```text
backend/json или backend/PostgreSQL
→ профиль
→ записи
→ чат
→ медиа-хранилище
```

Это мощно, но дороже в сопровождении: нужна база, storage, backup, поддержка сервера и полная ответственность за рабочие данные.

## Что меняем в P53

### 1. Запись и CRM

Экран записи остаётся прежним. Но источником данных становится YCLIENTS.

- `/yclients/services` → услуги из YCLIENTS.
- `/yclients/staff` → специалисты из YCLIENTS.
- `/yclients/dates` → доступные даты из YCLIENTS.
- `/yclients/times` → доступные окна из YCLIENTS.
- `/yclients/booking` → создание записи в YCLIENTS.
- `/yclients/bookings` → сначала пытается получить записи из YCLIENTS, потом fallback на технический cache/reference.
- `/yclients/bookings/:id/cancel` → отмена в YCLIENTS + обновление технической ссылки.

### 2. Профиль клиента

При входе backend может синхронизировать клиента в YCLIENTS, если включено:

```env
PROFILE_PROVIDER=yclients
YCLIENTS_CLIENT_UPSERT_ENDPOINT_TEMPLATE=...
```

Если endpoint ещё не известен — приложение не падает, а возвращает `skipped`. Это безопасно для поэтапного подключения.

### 3. Чат и фото/видео

Чат внутри приложения остаётся.

Клиент пишет в приложении → backend отправляет сообщение в Telegram → админ отвечает в Telegram → ответ приходит в приложение.

Фото/видео идут в Telegram как нормальные медиа. Backend может хранить локальный технический cache для отображения в приложении, но основной архив общения и файлов — Telegram.

### 4. Production env

Добавлены режимы:

```env
APP_OPERATING_MODEL=thin_proxy
BOOKING_PROVIDER=yclients
PROFILE_PROVIDER=yclients
CHAT_PROVIDER=telegram
CHAT_HISTORY_MODE=technical_index
CHAT_MEDIA_PRIMARY=telegram
FILE_STORAGE_DRIVER=telegram
```

В thin mode S3 больше не обязателен. PostgreSQL рекомендуется только как маленькая техническая БД.

## Что не ломаем

- Не переписываем Flutter-экраны.
- Не превращаем запись в простую ссылку.
- Не убираем чат из приложения.
- Не удаляем full-mode.
- Не удаляем юридические документы.
- Не удаляем Telegram-админку контента.

## Что осталось уточнить перед реальным подключением

1. Реальные YCLIENTS/Altegio ключи.
2. Реальные ID компании, услуг и специалистов.
3. Точный endpoint YCLIENTS для получения записей клиента по телефону.
4. Точный endpoint YCLIENTS для создания/обновления карточки клиента.
5. Точный регламент удаления/обезличивания клиента в YCLIENTS.
6. Реальные Telegram bot tokens и group/forum id.
7. Российский SMS-провайдер и ключ.
8. Production-сервер и домен API.
9. Маленькая production-БД для сессий, согласий и индексов сообщений.

## Итог аудита

P53 переводит проект в правильную экономичную модель: приложение остаётся полноценным и красивым, но YCLIENTS становится главной CRM, Telegram — главным архивом чата/медиа, а backend — безопасным тонким прокси.
