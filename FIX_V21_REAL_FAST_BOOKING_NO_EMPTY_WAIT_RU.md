# V21 — быстрая реальная запись без пустого ожидания

Сделано от текущей рабочей линии V18/V20, без возврата к идее старого клиентского кеша как источника правды.

## Исправлено

1. Экран `Запись` больше не должен очищаться и ждать пустым 5–10 секунд при переходе между вкладками.
   - `PremiumShell` теперь использует `IndexedStack`, вкладки сохраняют состояние.
   - Повторный вход в `Запись` не пересоздаёт экран заново.

2. Услуги и специалисты грузятся при старте приложения быстрее.
   - Стартовая загрузка каталога YCLIENTS вынесена раньше.
   - Профиль, записи и контент больше не блокируют первичный показ услуг/специалистов.

3. Специалисты не режутся по неполному ответу `book_staff?serviceId`.
   - Для выбранной услуги показываются все специалисты из каталога.
   - Доступность времени проверяется через `/times` по выбранному специалисту и дате.

4. Даты показываются сразу на 30 дней.
   - Клиент не видит пустой блок дат.
   - Свободное время для выбранного дня запрашивается live через YCLIENTS.

5. Исправлена неверная длительность/цена услуг в приложении.
   - Приложение больше не подставляет demo-длительность из fallback по индексу.
   - Если YCLIENTS не отдал длительность, поле остаётся пустым, а не показывает чужое значение.

6. Backend bootstrap улучшен.
   - Горизонт по умолчанию увеличен до 30 дней.
   - Для проверки доступности используются все специалисты, а не только неполный staff-filter.
   - Перед созданием записи слот всё равно проверяется свежим запросом в YCLIENTS.

## Важно

Свободное время не считается окончательной истиной до нажатия `Подтвердить запись`.
Перед созданием записи backend заново проверяет конкретный `serviceId + staffId + date + time` в YCLIENTS.
